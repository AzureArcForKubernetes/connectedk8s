# Troubleshoot Azure Arc-enabled Kubernetes error codes

Use this reference when an `az connectedk8s` command reports an error in the
`AZK8Snnnn` format. Find the code in the tables below, follow the resolution,
and retry the original command.

The code identifies the operation or failure category. The detailed text after
the code identifies the specific resource, endpoint, or underlying failure.
Use that detailed text to decide which resolution step applies.

The error catalog is introduced incrementally. Some codes are reserved for
call sites that have not yet migrated to standardized errors. DNS and outbound
connectivity codes, and diagnostic log-save failures, can also appear as
non-fatal diagnostic results. A non-fatal result needs action only when the
related check or command also fails.

## General and internal errors

| Code and name | What it means | How to resolve |
| --- | --- | --- |
| `AZK8S0001` `UnexpectedError` | The extension encountered an unclassified error. In version 1.11.5, `az connectedk8s show` also uses this code when Azure returns `ResourceNotFound`. | If the detailed error is `ResourceNotFound`, follow `AZK8S0405`. Otherwise, record the installed versions with `az version`, then run `az upgrade` and `az extension update --name connectedk8s`. Retry the original command once. If the error repeats, rerun that command with `--debug`, remove credentials, tokens, certificates, private keys, proxy details, and customer identifiers from the output, and contact support with the sanitized error and versions. |
| `AZK8S0002` `UnsupportedOperatingSystem` | The command is running on a host operating system other than Windows, Linux, or macOS. In version 1.11.5, current command paths display an unnumbered error; the client-proxy path records this classification in telemetry, while Helm installation uses a separate legacy fault type. The code is reserved for their migration to standardized console errors. | On Linux or macOS, run `uname -srm`; the first value must be `Linux` or `Darwin`. On Windows PowerShell, run `[System.Environment]::OSVersion.VersionString`; the result must identify Windows. The remaining values describe the kernel and processor architecture and don't determine this error. Run the latest Azure CLI and `connectedk8s` extension on a supported OS. See [Install Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli) for supported installation options and OS-version details. |
| `AZK8S0003` `UnsupportedProvisionedClusterOperation` | The requested `az connectedk8s` operation isn't available for an AKS Arc provisioned cluster. Current command paths record this classification in telemetry but display an unnumbered error; the code is reserved for their migration to standardized console errors. | Run `az connectedk8s show -g "<resource-group>" -n "<cluster-name>" --query kind -o tsv`; this error applies when the result is `ProvisionedCluster`. Use the `az aksarc` command named in the detailed error for lifecycle operations: `update`, `delete`, or `upgrade`. Run `az aksarc <command> --help` before retrying. Manage supported features through cluster extensions as directed by the detailed error. Connecting an existing cluster with `az connectedk8s connect` doesn't convert it into an AKS Arc provisioned cluster. |

## Configuration and input errors

| Code and name | What it means | How to resolve |
| --- | --- | --- |
| `AZK8S0100` `InvalidArgumentValue` | One or more command arguments are invalid. | Read the detailed message, run `az connectedk8s <command> --help`, and correct the named value or format. |
| `AZK8S0101` `UpdateNoParameters` | `az connectedk8s update` was called without a setting to change. | Supply at least one supported update option. Use `az connectedk8s update --help` to list the options. |
| `AZK8S0102` `UpdateProxyParameterConflict` | `az connectedk8s update` was given proxy settings and `--disable-proxy` in the same command. | To update the proxy settings, rerun without `--disable-proxy`, for example: `az connectedk8s update -g "<resource-group>" -n "<cluster-name>" --proxy-https "<https-proxy-url>" --proxy-http "<http-proxy-url>" --proxy-skip-range "<host-or-cidr>,<additional-host-or-cidr>"`. Add `--proxy-cert "<certificate-path>"` only when required. To disable all proxy settings, run `az connectedk8s update -g "<resource-group>" -n "<cluster-name>" --disable-proxy` without proxy or bypass options. |
| `AZK8S0103` `ProxyCertificatePathNotFound` | The proxy certificate file cannot be found. | On Windows run `Test-Path -LiteralPath "<certificate-path>" -PathType Leaf`; expect `True`. On Linux or macOS run `test -f "<certificate-path>" && test -r "<certificate-path>"; echo $?`; expect exit code `0`. Retry with the absolute path if the check fails. |
| `AZK8S0104` `InvalidLocation` | The Azure location is not in the current `Microsoft.Kubernetes/connectedClusters` supported-location list. | Follow the [location steps](troubleshoot-azure-resources-helm-diagnostics.md#azk8s0104-invalidlocation) and retry with the canonical name of a supported region. |
| `AZK8S0105` `PrivateLinkScopeLocationMismatch` | The Azure Arc Private Link Scope and the requested connected cluster are in different locations. | Run `az resource show --ids "<private-link-scope-id>" --query "{type:type,location:location}" -o yaml`; `type` must be `Microsoft.HybridCompute/privateLinkScopes`. Compare the returned location with the `--location` value passed to `az connectedk8s connect`. Retry with a matching supported location or an approved scope in the requested region. **Fixed when:** the two locations match case-insensitively and the retry no longer reports `AZK8S0105`; later independent onboarding checks can still fail. |
| `AZK8S0106` `InvalidGatewayArmId` | The gateway resource ID is malformed or does not identify a `Microsoft.HybridCompute/gateways` resource. | Run `az resource show --ids "<gateway-resource-id>" --query "{id:id,type:type}" -o yaml`. An invalid-ID or `ResourceNotFound` response means you need the ARM ID of an existing Azure Arc gateway. Otherwise, `type` must be `Microsoft.HybridCompute/gateways`; pass the returned `id` unchanged to `--gateway-resource-id`. **Fixed when:** the retry no longer reports `AZK8S0106`; later independent onboarding checks can still fail. |
| `AZK8S0107` `ProxyBypassStateInvalid` | The saved Arc proxy-bypass ownership record is unreadable or does not match the current `global.noProxy` Helm value. This can happen when Helm values are changed outside the CLI. The command stops before changing proxy or Helm settings. | Do not guess which `global.noProxy` entries the CLI owns. Run `kubectl get configmap azure-clusterconfig -n azure-arc -o jsonpath="{.data.AZURE_ARC_HELM_NAMESPACE}{'\n'}"` to read the Helm release namespace without displaying other ConfigMap data. Collect and sanitize `helm get values azure-arc --namespace "<release-namespace>"`, then contact support to reconcile `connectedk8sCli.arcProxyBypass` with `global.noProxy`. |

### List supported regions

To list the regions that support Azure Arc-enabled Kubernetes connected
clusters, run:

```azurecli
az provider show --namespace Microsoft.Kubernetes --query "resourceTypes[?resourceType=='connectedClusters'].locations | [0][]" --output table
```

## Kubeconfig and cluster access errors

| Code and name | What it means | How to resolve |
| --- | --- | --- |
| `AZK8S0200` `KubeconfigLoadFailed` | Azure CLI could not read or parse kubeconfig. | Follow the [kubeconfig loading steps](troubleshoot-cluster-access-networking.md#azk8s0200-kubeconfigloadfailed). Run `kubectl --kubeconfig "<path>" config get-contexts` and `config current-context`; they must list the intended context. If parsing succeeds but `/version` fails, loading is fixed; continue with `AZK8S0202`. **Fixed when:** Azure CLI parses the same file and context. |
| `AZK8S0201` `ConfigMapReadFailed` | A required Kubernetes ConfigMap could not be read. | Use the name and namespace from the detailed error. Run `kubectl auth can-i get configmap/"<name>" -n "<namespace>"` and `kubectl get configmap "<name>" -n "<namespace>" -o name`; expect `yes` and `configmap/<name>`. Don't display its data. **Fixed when:** both checks succeed and the original command reads the ConfigMap. |
| `AZK8S0202` `KubernetesConnectivityFailed` | The Kubernetes `/version` request failed. | Follow the [Kubernetes connectivity steps](troubleshoot-cluster-access-networking.md#azk8s0202-kubernetesconnectivityfailed) for authentication, TLS, DNS, routing, firewall, VPN, and API health. **Fixed when:** `/version` returns `gitVersion` with the same kubeconfig and context. |
| `AZK8S0203` `KubernetesDistributionDetectionFailed` | The extension could not identify the Kubernetes distribution. | Run `kubectl get nodes -o json` to verify node discovery. It should exit successfully and return at least one object in `items`. If it reports an API access error, follow `AZK8S0202`. If nodes are returned, retry once with the latest extension or pass a supported `--distribution` value listed by `az connectedk8s connect --help`; if detection still throws, collect debug output and escalate. |
| `AZK8S0204` `KubernetesNamespaceGetFailed` | The extension could not determine or read a required namespace. | Use the namespace in the detailed error. Run `kubectl auth can-i get namespace/"<namespace>"` and `kubectl get namespace "<namespace>" -o name`; expect `yes` and `namespace/<namespace>`. **Fixed when:** both checks succeed and the command reads the namespace. |
| `AZK8S0205` `LinuxNodeNotFound` | No Linux node is available for Azure Arc agents. | Run `kubectl get nodes -l kubernetes.io/os=linux -o wide`. At least one row must appear; then confirm a candidate reports `Ready` and isn't cordoned before retrying. If no rows appear, add or correctly label a supported Linux node. **Fixed when:** Arc detects a Linux node and its pods can schedule. |
| `AZK8S0206` `ClusterRoleBindingCreateForbidden` | The Kubernetes identity cannot create ClusterRoleBindings. | Run `kubectl auth can-i create clusterrolebindings.rbac.authorization.k8s.io`; it must return `yes`. Have the cluster administrator grant the required onboarding permission, then retry with the same kubeconfig identity. **Fixed when:** authorization returns `yes` and onboarding creates the binding. |
| `AZK8S0207` `KubernetesConfigurationLoadFailed` | Kubernetes client configuration initialization failed. | Run `kubectl --kubeconfig "<path>" config get-contexts` and `config current-context`; both must succeed. Then run `kubectl --kubeconfig "<path>" --context "<context>" get --raw=/version`. Treat later authentication or network failures as `AZK8S0202`. |
| `AZK8S0208` `KubernetesPrivateKeyInjectionFailed` | The extension could not prepare the `azure-arc` namespace or create or update the onboarding private-key Secret. | Run `kubectl get namespace azure-arc -o name`. `NotFound` means onboarding needs `kubectl auth can-i create namespaces`; an existing namespace needs `kubectl auth can-i patch namespace/azure-arc`. If the namespace exists, run `kubectl get secret azure-arc-connect-privatekey -n azure-arc -o name` only to test existence. `NotFound` means onboarding needs `kubectl auth can-i create secrets -n azure-arc`; an existing Secret needs `kubectl auth can-i update secret/azure-arc-connect-privatekey -n azure-arc`. Each required permission must return `yes`. If one returns `no`, ask the cluster administrator to grant that verb on that resource to the kubeconfig identity. If all required checks return `yes`, correct the quota or admission-policy denial named in the detailed error. Don't display the Secret. |
| `AZK8S0209` `ConfigMapWriteFailed` | A required ConfigMap could not be created or updated. | Use the name and namespace from the detailed error, then run `kubectl get configmap "<name>" -n "<namespace>" -o name` only to test existence. `NotFound` means the extension needs `kubectl auth can-i create configmaps -n "<namespace>"`; an existing ConfigMap needs `kubectl auth can-i update configmap/"<name>" -n "<namespace>"`. The applicable permission must return `yes`. If it returns `no`, ask the cluster administrator to grant that verb on the ConfigMap to the kubeconfig identity. If it returns `yes`, correct the quota or admission-policy denial named in the detailed error. Don't display the ConfigMap data. |

## Network and connectivity errors

| Code and name | What it means | How to resolve |
| --- | --- | --- |
| `AZK8S0300` `DataPlaneHealthCheckFailed` | The Azure Arc data-plane endpoint health check failed. | Follow the [data-plane health-check steps](troubleshoot-cluster-access-networking.md#azk8s0300-dataplanehealthcheckfailed). |
| `AZK8S0301` `DnsNxDomain` | DNS returned `NXDOMAIN` for a required endpoint. | Follow [Determine whether DNS is blocking connectivity](troubleshoot-cluster-access-networking.md#determine-whether-dns-is-blocking-connectivity) with the hostname from the error. **Fixed when:** the in-cluster `nslookup` returns one or more addresses instead of `NXDOMAIN`. |
| `AZK8S0302` `DnsTimeout` | DNS resolution did not complete before timeout. | Follow [Determine whether DNS is blocking connectivity](troubleshoot-cluster-access-networking.md#determine-whether-dns-is-blocking-connectivity), then repeat the in-cluster `nslookup`. **Fixed when:** it returns an address before timeout. |
| `AZK8S0303` `DnsServerFailure` | The DNS server returned `SERVFAIL`. | Follow [Determine whether DNS is blocking connectivity](troubleshoot-cluster-access-networking.md#determine-whether-dns-is-blocking-connectivity) and correct the configured resolver's forwarding or DNSSEC failure. **Fixed when:** the same in-cluster lookup returns an address without `SERVFAIL`. |
| `AZK8S0304` `DnsNoServersReachable` | The cluster could not reach any configured DNS server. | Follow [Determine whether DNS is blocking connectivity](troubleshoot-cluster-access-networking.md#determine-whether-dns-is-blocking-connectivity) and restore UDP and TCP port 53 access to a configured resolver. **Fixed when:** the in-cluster lookup reaches the resolver and returns an address. |
| `AZK8S0305` `DnsCommunicationsError` | A network error interrupted communication with DNS. | Follow [Determine whether DNS is blocking connectivity](troubleshoot-cluster-access-networking.md#determine-whether-dns-is-blocking-connectivity), then repeat the lookup after correcting routes, packet loss, policy, or resolver availability. **Fixed when:** repeated in-cluster lookups complete reliably. |
| `AZK8S0306` `OnboardingOutboundConnectivityFailed` | A required onboarding endpoint is unreachable. | The detailed error identifies the endpoint that returned no HTTP response. Compare that hostname with the [network requirements](https://learn.microsoft.com/azure/azure-arc/kubernetes/network-requirements) and allow its documented outbound route in the applicable firewall or proxy. For an existing resource, run `az connectedk8s troubleshoot -g "<resource-group>" -n "<cluster-name>"` and find that endpoint in the printed connectivity results. Response code `000` means the request couldn't connect; any HTTP response proves basic reachability. **Fixed when:** the named endpoint no longer reports `000`. |
| `AZK8S0307` `ClusterConnectOutboundConnectivityFailed` | A required Cluster Connect endpoint is unreachable. | Run `az connectedk8s troubleshoot -g "<resource-group>" -n "<cluster-name>"` and find the Cluster Connect endpoint named in the error among the printed connectivity results. Response code `000` means no HTTP response was received; any HTTP response proves basic reachability. For each endpoint reporting `000`, allow the outbound HTTPS or WebSocket route documented in the [network requirements](https://learn.microsoft.com/azure/azure-arc/kubernetes/network-requirements) through the applicable firewall or proxy, then retry `az connectedk8s proxy`. **Fixed when:** the named endpoint no longer reports `000` and proxy traffic succeeds. |
| `AZK8S0308` `OutboundEndpointNonSuccessResponse` | An endpoint returned HTTP 4xx or 5xx. Because an HTTP response was received, the connectivity check treats the endpoint as reachable and records this code as a non-fatal diagnostic. | Don't change firewall rules or credentials for this diagnostic code alone; the HTTP response already proves basic reachability. If the related operation also fails with its own `401`, sign in again or refresh the credential used by that operation. For an operation-level `403`, verify its Azure or Kubernetes RBAC permission. Retry operation-level `429` or `5xx` responses with backoff, and escalate if the same status persists. **Successful classification:** any HTTP response establishes basic endpoint reachability. |
| `AZK8S0309` `CertificatePulldownFailed` | Agent identity or certificate synchronization did not complete before the Helm timeout. | Run `kubectl get pods -n azure-arc -o wide` to find agents that aren't running and ready. Run `kubectl get events -n azure-arc --sort-by=.lastTimestamp` and inspect the newest warnings for the affected pods, including scheduling, image-pull, DNS, or egress failures. Run `kubectl get secret azure-identity-certificate -n azure-arc -o name` only to test existence: it returns `secret/azure-identity-certificate` when synchronization completed and `NotFound` when it didn't; don't display the Secret. Correct the first concrete pod or connectivity failure and retry once. If the Secret remains absent after another timeout, collect diagnostics and contact support without deleting the resource or release. **Fixed when:** the Secret exists and Arc agents become ready. |

See [Azure Arc-enabled Kubernetes network requirements](https://learn.microsoft.com/azure/azure-arc/kubernetes/network-requirements)
for the current endpoint and port list.

## Azure resource operation errors

| Code and name | What it means | How to resolve |
| --- | --- | --- |
| `AZK8S0400` `ConnectedClusterCreateFailed` | Azure Resource Manager could not create the connected cluster resource. | Follow the [resource-creation steps](troubleshoot-azure-resources-helm-diagnostics.md#azk8s0400-connectedclustercreatefailed). **Fixed when:** `az connectedk8s show` returns a nonempty ID and `provisioningState: Succeeded`. |
| `AZK8S0401` `ConnectedClusterUpdateFailed` | Azure Resource Manager could not update the connected cluster resource. | Run `az connectedk8s show -g "<resource-group>" -n "<cluster-name>" --query "{id:id,state:provisioningState}" -o yaml` and `az lock list -g "<resource-group>" -o table`. Correct the detailed RBAC, lock, policy, or concurrency error. Retry once only for `429`, `5xx`, or a transient conflict. **Fixed when:** the original update succeeds and the subsequent query reports `state: Succeeded`; otherwise escalate with the ARM status and correlation ID. |
| `AZK8S0402` `ConnectedClusterDeleteFailed` | Azure Resource Manager could not delete the connected cluster resource. | Run `az connectedk8s show -g "<resource-group>" -n "<cluster-name>" --query "{id:id,state:provisioningState}" -o yaml` and `az lock list -g "<resource-group>" -o table`. A `ReadOnly` or `CanNotDelete` lock that applies to the resource selects the lock-remediation path; ask the lock owner to remove that applicable lock. If no applicable lock appears, follow the permission, policy, or dependency failure named in the detailed ARM error. Then retry the supported delete once. Don't force-delete or manually remove cluster resources. **Fixed when:** `az connectedk8s show` reports resource not found. |
| `AZK8S0403` `ClusterAlreadyOnboarded` | The Kubernetes cluster already contains Azure Arc onboarding state. | Run `kubectl config current-context`, then read only the registration names with `kubectl get configmap azure-clusterconfig -n azure-arc -o jsonpath="{.data.AZURE_RESOURCE_GROUP}{'\n'}{.data.AZURE_RESOURCE_NAME}{'\n'}"`. Target that existing Azure resource. If ownership is unclear, stop and contact support before offboarding. |
| `AZK8S0404` `ConnectedClusterResourceAlreadyExists` | The requested Azure resource name is already in use in the resource group. | Run `az connectedk8s show -g "<resource-group>" -n "<cluster-name>" --query "{id:id,state:provisioningState}" -o yaml`. Then read only the cluster's registration names with `kubectl get configmap azure-clusterconfig -n azure-arc -o jsonpath="{.data.AZURE_RESOURCE_GROUP}{'\n'}{.data.AZURE_RESOURCE_NAME}{'\n'}"`. If those names match the resource group and name in the Azure resource ID, use the existing resource. If they differ or can't be read, choose another name or contact support; don't remove the existing resource until ownership is verified. |
| `AZK8S0405` `ConnectedClusterResourceNotFound` | The named connected cluster resource does not exist in the selected scope. In version 1.11.5, `az connectedk8s show` reports the underlying `ResourceNotFound` as `AZK8S0001`; this code is reserved for migration of that path. | Run `az account show --query id -o tsv` and `az connectedk8s show -g "<resource-group>" -n "<cluster-name>" --query id -o tsv`. Select the intended subscription or correct the names. If it should exist but still returns `404`, escalate rather than recreating it blindly. **Fixed when:** `show` returns the intended full resource ID. |
| `AZK8S0406` `InvalidDeleteRequest` | The current kubeconfig context points to a cluster whose Arc registration does not match the Azure resource being deleted. | Compare `az connectedk8s show -g "<resource-group>" -n "<cluster-name>" --query id -o tsv` with the names from `kubectl get configmap azure-clusterconfig -n azure-arc -o jsonpath="{.data.AZURE_RESOURCE_GROUP}{'\n'}{.data.AZURE_RESOURCE_NAME}{'\n'}"`. Switch to the matching context; never bypass a mismatch with force deletion. |
| `AZK8S0407` `ResourceProviderFetchFailed` | Azure CLI could not read resource-provider metadata. In version 1.11.5, the current path records this classification in telemetry but displays an unnumbered ARM request error. The code is reserved for its migration to a standardized console error. | Run `az account show --query "{subscription:id,tenant:tenantId,user:user.name}" -o yaml`; it must return the intended account scope. Then run `az provider show --namespace Microsoft.Kubernetes --query "{namespace:namespace,state:registrationState}" -o yaml`. An authentication, authorization, DNS, proxy, or timeout error identifies what blocks the management request. Retry after transient Azure errors and review any policy denial named in the detailed error. **Fixed when:** the provider query succeeds and the original command continues. |
| `AZK8S0408` `ConnectedClusterProviderNotRegistered` | `Microsoft.Kubernetes` is not registered in the subscription. | Run `az provider register --namespace Microsoft.Kubernetes`, wait until `az provider show --namespace Microsoft.Kubernetes --query registrationState --output tsv` returns `Registered`, then retry. **Fixed when:** registration reports `Registered` and the original command proceeds. |
| `AZK8S0409` `ConnectedClusterResourceIdMissing` | Azure returned a connected cluster object without a usable resource ID. | Refresh the resource with `az connectedk8s show`. Retry with the latest extension; if the ID remains absent, collect debug output and contact support. **Fixed when:** `az connectedk8s show --query id --output tsv` returns a complete resource ID. |

## Helm and agent lifecycle errors

| Code and name | What it means | How to resolve |
| --- | --- | --- |
| `AZK8S0500` `HelmReleaseInstallFailed` | Installing or upgrading the Azure Arc agent Helm release failed. | Follow the [Helm release steps](troubleshoot-azure-resources-helm-diagnostics.md#azk8s0500-helmreleaseinstallfailed). **Fixed when:** Helm reports `deployed` and required Arc workloads become ready. |
| `AZK8S0501` `HelmReleaseDeleteFailed` | The Azure Arc Helm release could not be removed. | Run `helm list --all --all-namespaces --filter "^azure-arc$"` to determine whether the release remains and, if so, read its namespace and status from that row. A successful command with no row means Helm no longer lists the release. If a row remains, run `helm status azure-arc -n "<release-namespace>"` to inspect its current state and managed resources. An API or RBAC error from either command identifies access that must be restored. Correct a blocking resource only when the original delete error or Helm status explicitly names it; if neither does, contact support rather than inspecting or clearing finalizers generically. Retry the original `az connectedk8s delete` once after correction. Don't manually delete the release, namespace, or Arc resources. **Fixed when:** the supported delete succeeds and Helm no longer lists the release. |
| `AZK8S0502` `HelmChartPullFailed` | The Arc agent Helm chart could not be downloaded. | Use the registry hostname, chart version, and Helm error from the detailed output. Run `nslookup "<registry-hostname>"`; it must return an address, otherwise correct local DNS or proxy resolution. Check the filesystem containing `$HOME/.azure` with `df -h "$HOME/.azure"` on Linux or macOS or `Get-PSDrive -PSProvider FileSystem` on Windows; free enough space for the chart export if it is full. If both checks pass, use the Helm error to correct the named proxy, TLS, authentication, or registry failure. Retry once, then escalate with sanitized debug output if the same managed-artifact pull fails. |
| `AZK8S0503` `HelmChartExportFailed` | The downloaded Helm chart could not be exported locally. | On Windows run `Test-Path "$HOME/.azure/AzureArcCharts"` and `Get-PSDrive -PSProvider FileSystem`; on Linux or macOS run `test -w "$HOME/.azure" && df -h "$HOME/.azure"`. Correct space, permissions, or endpoint-security blocking in the extension-managed directory and retry once. |
| `AZK8S0504` `HelmRepositoryAddFailed` | Helm could not add the configured chart repository. | Use the repository name and URL from debug output and run `helm repo add "<name>" "<url>"`. Correct its DNS, proxy, CA, or filesystem error, then retry the original operation. **Fixed when:** Helm reports that the repository was added and chart retrieval continues. |
| `AZK8S0505` `HelmReleaseListFailed` | Helm could not list releases in the cluster. | Verify kubeconfig and namespace access, then run `helm list --all-namespaces` to expose the underlying authentication or API error. **Fixed when:** that command lists releases without an error. |
| `AZK8S0506` `AgentStateTimeout` | Azure Arc agents did not reach the expected state before timeout. | Run `az connectedk8s show -g "<resource-group>" -n "<cluster-name>" --query arcAgentProfile.agentState -o tsv` to read the state last reported to Azure; any value other than `Succeeded` confirms that the agents haven't converged but doesn't identify why. Run `kubectl get pods -n azure-arc -o wide` to find agents that aren't running and ready, then run `kubectl get events -n azure-arc --sort-by=.lastTimestamp` and inspect the newest warnings for those pods. Scheduling, mount, or image-pull events identify an in-cluster startup problem; DNS, timeout, or connection errors identify connectivity to investigate. Correct the first concrete failure. **Fixed when:** agent state returns `Succeeded`. |
| `AZK8S0507` `KeyPairGenerationFailed` | The local RSA key pair required for onboarding could not be generated. | On Windows run `Test-Path $env:TEMP` and `Get-PSDrive -PSProvider FileSystem`; on Linux or macOS run `test -w "${TMPDIR:-/tmp}" && df -h "${TMPDIR:-/tmp}"`. No public command reproduces the extension's RSA generation; retry once after correcting local access or space, then escalate. |
| `AZK8S0508` `ReleaseNamespaceNotFound` | The namespace containing the Azure Arc Helm release was not found. | Run `kubectl config current-context`, `helm list --all-namespaces --filter "^azure-arc$"`, and `kubectl get namespace azure-arc`. If the Azure resource exists but the release or namespace is absent, collect diagnostics and contact support; no safe generic command reconstructs missing ownership state. **Fixed when:** the intended release namespace is found or support completes a supported recovery. |
| `AZK8S0509` `HelmValuesGetFailed` | Helm could not read the Arc release values. | Find the namespace with `helm list --all-namespaces --filter "^azure-arc$"`. Test access without sharing output: on Linux or macOS run `helm get values azure-arc -n "<release-namespace>" > /dev/null`; in PowerShell run `helm get values azure-arc -n "<release-namespace>" \| Out-Null` and inspect `$LASTEXITCODE`. **Fixed when:** the command exits with code `0`. |
| `AZK8S0510` `HelmNotInstalled` | Helm is not available on `PATH` in an environment where the extension expects a preinstalled client, such as AGC. | Install Helm 3 or later and add `helm` to `PATH`. In other environments, the extension normally downloads its managed binary. **Fixed when:** `helm version` succeeds in the same environment. |
| `AZK8S0511` `HelmVersionTooOld` | The installed Helm version is below the supported minimum. | Upgrade Helm 3 and verify with `helm version`. |
| `AZK8S0512` `HelmTimeoutPendingOrUnschedulable` | Arc agent pods remain pending or cannot be scheduled. | Run `kubectl get pods -n azure-arc --field-selector=status.phase=Pending -o wide`, then `kubectl describe pod -n azure-arc "<pending-pod>"`. Correct the first `FailedScheduling` event. **Fixed when:** affected pods leave `Pending` and report ready. |
| `AZK8S0513` `HelmTimeoutImagePullFailed` | Arc agent images could not be pulled. | Run `kubectl get pods -n azure-arc -o wide`, `kubectl get events -n azure-arc --sort-by=.lastTimestamp`, and `kubectl describe pod -n azure-arc "<affected-pod>"`. Use the image-pull event to identify the registry hostname and cause. For a timeout or connection error, allow the registry's documented outbound HTTPS route in the applicable firewall, proxy, or network policy. For `Unauthorized` or `denied`, correct the registry or proxy authentication named in the event. **Fixed when:** the image pulls and the pod becomes ready. |
| `AZK8S0514` `HelmTimeout` | Agent installation did not finish before the generic Helm timeout. | Run `kubectl get pods -n azure-arc -o wide` and `kubectl get events -n azure-arc --sort-by=.lastTimestamp`; for each non-ready pod run `kubectl describe pod -n azure-arc "<pod>"` and `kubectl logs -n azure-arc "<pod>" --all-containers`. Fix the first concrete failure, then retry once. **Fixed when:** Helm finishes and required pods become ready. |
| `AZK8S0515` `HelmClientError` | The extension-managed Helm process failed to execute. | Use the Helm path and operating-system error in the detailed output. On Windows, `Test-Path -LiteralPath "<helm-path>"` must return `True`; on Linux or macOS, `test -x "<helm-path>"` must exit with code `0`. A failed check means the configured or managed binary is missing or not executable; restore that path or its execute permission. If the check succeeds, permit the signed binary in endpoint-security controls and retry once. System `helm version` may test a different binary. Escalate with the path and sanitized error if execution still fails. |

## Pre-onboarding diagnostic errors

| Code and name | What it means | How to resolve |
| --- | --- | --- |
| `AZK8S0600` `PrediagnosticsFailed` | One or more pre-onboarding checks failed. | Read each individual check and `AZK8S03xx` result printed above this summary and follow that row's procedure. Rerun the original onboarding command with `--debug`; don't troubleshoot the summary code alone. **Fixed when:** every mandatory precheck reports `Passed`. |
| `AZK8S0601` `PrediagnosticsJobExecutionFailed` | The diagnostic Kubernetes job did not execute successfully. | Run `kubectl get job cluster-diagnostic-checks-job -n azure-arc-release -o wide`, `kubectl get pods -n azure-arc-release -l job-name=cluster-diagnostic-checks-job -o wide`, and `kubectl logs -n azure-arc-release job/cluster-diagnostic-checks-job --all-containers`. Correct the reported creation, image, runtime, or API failure and retry once. **Fixed when:** the Job completes and returns results. |
| `AZK8S0602` `PostDiagnosticPrecheckFailed` | A required validation after diagnostics failed. | Use the check name and reason in the detailed error to select the matching row: use `AZK8S0200`-`AZK8S0209` for kubeconfig, API access, namespace, or RBAC checks; `AZK8S0300`-`AZK8S0308` for data-plane, DNS, or outbound connectivity; and `AZK8S0601` or `AZK8S0603`-`AZK8S0607` for diagnostic Job, result, log, or Helm failures. Run that row's command and meet its stated success condition. If the named check succeeds but `AZK8S0602` repeats once on an unchanged cluster, attach the saved precheck logs and escalate; no generic command reproduces every post-check. |
| `AZK8S0603` `PrediagnosticsIncomplete` | Diagnostics ended without a conclusive result. | Run `kubectl get job cluster-diagnostic-checks-job -n azure-arc-release -o yaml` to determine whether the Job completed, then `kubectl get pods -n azure-arc-release -l job-name=cluster-diagnostic-checks-job -o wide` to identify a failed or non-running pod. Use `kubectl logs -n azure-arc-release job/cluster-diagnostic-checks-job --all-containers` to find the check that produced no result. If the Job or pod failed, correct the first image, scheduling, API, DNS, or egress error and retry once. If the Job completed but a required result remains inconclusive, attach the saved precheck logs when contacting support. **Fixed when:** every required check returns a conclusive result. |
| `AZK8S0604` `PrediagnosticsJobNotScheduled` | The diagnostic Job object wasn't observed. | Run `kubectl get job cluster-diagnostic-checks-job -n azure-arc-release -o wide`, `kubectl get pods -n azure-arc-release -o wide`, and `kubectl get events -n azure-arc-release --sort-by=.lastTimestamp`. Correct the first policy, quota, or object-creation denial, then retry once. **Fixed when:** the Job and its pod are created. |
| `AZK8S0605` `PrediagnosticsJobNotComplete` | The diagnostic job exceeded its timeout. | Run `kubectl get pods -n azure-arc-release -l job-name=cluster-diagnostic-checks-job -o wide`, `kubectl describe pod -n azure-arc-release "<pod>"`, and `kubectl logs -n azure-arc-release "<pod>" --all-containers`. Fix the first hang, image, DNS, egress, or pressure event and retry once. **Fixed when:** the Job finishes within its timeout. |
| `AZK8S0606` `PrediagnosticsLogSaveFailed` | The extension could not save diagnostic logs locally. | Use the log path in the error. On Windows run `Test-Path -LiteralPath (Split-Path "<log-path>")` and `Get-PSDrive -PSProvider FileSystem`; on Linux or macOS run `test -w "$(dirname "<log-path>")" && df -h "$(dirname "<log-path>")"`. Rerun from a writable directory only when saved logs are needed. **Fixed when:** logs save successfully; completed diagnostic results remain valid without them. |
| `AZK8S0607` `PrediagnosticsHelmInstallFailed` | The diagnostic Helm release could not be installed. | Run `helm list --all-namespaces --filter "^cluster-diagnostic-checks$"` and `kubectl get events -n azure-arc-release --sort-by=.lastTimestamp`; if listed, run `helm status cluster-diagnostic-checks -n azure-arc-release`. Correct the reported RBAC, policy, image, or quota failure and retry once. Don't manually remove diagnostic resources. **Fixed when:** the release installs and its Job starts. |

## Feature errors

| Code and name | What it means | How to resolve |
| --- | --- | --- |
| `AZK8S0700` `CustomLocationsEnableFailed` | The custom locations feature could not be enabled. | Follow the [Custom Locations steps](troubleshoot-features-cluster-connect.md#azk8s0700-customlocationsenablefailed). `az provider show -n Microsoft.ExtendedLocation --query registrationState -o tsv` must return `Registered`, and the object-ID query must return a GUID. **Fixed when:** `enable-features` completes; creating a custom location is a separate operation. |
| `AZK8S0701` `CustomLocationsOidFetchFailed` | The extension could not query Microsoft Graph for the Custom Locations service principal object ID. This can be a non-fatal diagnostic when a value was supplied manually. | Run `az ad sp show --id bc313c14-388c-4e7d-a58e-70017303ee3b --query id -o tsv`; expect a GUID. Use that object ID with `--custom-locations-oid`. If an administrator supplies it and enablement still fails, stop retrying and have them reverify it. |
| `AZK8S0702` `CustomLocationsRegistrationCheckFailed` | The custom locations resource-provider registration could not be verified. | Run `az provider show -n Microsoft.ExtendedLocation --query registrationState -o tsv`. If needed, run `az provider register -n Microsoft.ExtendedLocation`, then repeat `show` until it returns `Registered`. **Fixed when:** registration reports `Registered` and feature enablement continues. |

See [Create and manage custom locations on Azure Arc-enabled Kubernetes](https://learn.microsoft.com/azure/azure-arc/kubernetes/custom-locations)
for current prerequisites and permissions.

## Client proxy errors

| Code and name | What it means | How to resolve |
| --- | --- | --- |
| `AZK8S0800` `ClientProxyDownloadFailed` | The Cluster Connect client proxy binary could not be downloaded or prepared. | Rerun `az connectedk8s proxy -g "<resource-group>" -n "<cluster-name>" --debug` and use the reported registry and installation directory. Verify that directory is writable and has free space, and that endpoint security permits the signed binary. Retry once; then escalate with sanitized debug output. |
| `AZK8S0801` `ClientProxyPortInUse` | The requested local API port or the proxy's internal port is already in use. | Follow the [port conflict steps](troubleshoot-features-cluster-connect.md#azk8s0801-clientproxyportinuse). **Fixed when:** the proxy remains running and listens on both selected ports. |
| `AZK8S0802` `ClientProxyStartFailed` | The downloaded client proxy process did not start successfully. | Run `az connectedk8s proxy -g "<resource-group>" -n "<cluster-name>" --port "<unused-port>" --debug`. On Windows check reported ports with `Get-NetTCPConnection -LocalPort <api-port>,<internal-port> -State Listen`; on Linux use `ss -ltn`. If it never listens, collect stderr and endpoint-security events and escalate after one retry. **Fixed when:** the process starts and listens. |
| `AZK8S0803` `ClientProxyConfigCreateFailed` | The client proxy configuration file could not be created, or an existing configuration file could not be removed. | Use the installation directory from debug output. On Windows run `Test-Path -LiteralPath "<directory>"` and `Get-PSDrive -PSProvider FileSystem`; on Linux or macOS run `test -w "<directory>" && df -h "<directory>"`. Don't manually remove `config.yml`; retry once, then escalate if replacement still fails. |
| `AZK8S0804` `ClientProxyClosed` | The client proxy process exited while `az connectedk8s proxy` was monitoring it. | Follow the [proxy exit steps](troubleshoot-features-cluster-connect.md#azk8s0804-clientproxyclosed). **Fixed when:** the proxy remains running and `/version` succeeds through its generated context. |
| `AZK8S0805` `ClusterCredentialsGetFailed` | Azure CLI could not obtain credentials for Cluster Connect. In version 1.11.5, the current path records this classification in telemetry but displays an unnumbered `Failed to get credentials` error. The code is reserved for its migration to a standardized console error. | Follow the [Cluster Connect credential steps](troubleshoot-features-cluster-connect.md#azk8s0805-clustercredentialsgetfailed) when the code or unnumbered message appears. **Fixed when:** the proxy remains running and `/version` succeeds through its generated context. |

## Contact support

If the resolution does not fix the problem, provide:

- The `AZK8Snnnn` code and complete sanitized error text.
- Azure CLI and extension versions from `az version`.
- The command name and UTC timestamp, without credentials or tokens.
- The correlation or request ID and Azure cloud or region when reported.
- The subscription, resource group, and cluster identifiers through the secure
  support channel; replace them with stable placeholders in shared logs.
- Sanitized `az connectedk8s troubleshoot` output.
- Relevant `azure-arc` pod status, events, and logs.
- The diagnostic command results and expected-result comparison from the
  matching detailed procedure.
